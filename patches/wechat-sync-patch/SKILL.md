# 微信双通道同步（手机 + 桌面）

给 `dsh-wechat-plugin` 打的一层补丁，让微信消息和桌面界面真正连起来：

- **桌面任何会话任务完成** → 手机收到「✅ 桌面任务完成」
- **桌面弹出选择/审批，5–10 秒没人答** → 自动转到手机，手机上答也一样生效
- **微信绑定的会话** → 桌面和手机同时弹，谁先答用谁，另一边收到「（已在桌面回答）」提示
- **手机上答完** → 桌面那个选择框自动消失，不用手动关

原版插件只做「绑定的会话双向收发」，上面这四条都没有。

## 前置条件

1. 装好 DSH 桌面应用。
2. 装好 `dsh-wechat-plugin`，版本必须是 **0.46.0**（补丁是照这个版本的源码位置做的，别的版本位置对不上）。
3. 已经用你自己的微信 bot 完成一次绑定（这一步跟补丁无关，按插件 README 走）。

版本不对就先装对版本：

```bash
cd ~/.dsh/profiles/desktop
pnpm add dsh-wechat-plugin@0.46.0
```

## 安装

```bash
# 1. 先看会改哪个文件（不会写入）
python scripts/install.py

# 2. 确认无误再写
python scripts/install.py --apply

# 3. 验证（应该看到 7 个标记全部达标）
python scripts/install.py --check
```

装完**必须重启一次 DSH 桌面应用**才生效。插件没有热重载。

## 验证是否真的生效

重启后，找一台**不是**微信绑定的会话，随便让它做点小事。做完后手机上应该收到一条「✅ 桌面任务完成」。

再试选择：让它问你一个问题，桌面上会弹出选择框。**什么都不点**，等 8 秒左右，手机上应该收到同一条问题。

## 调「多久没人答才转手机」

默认 8 秒。改环境变量即可，不用重新打补丁：

```bash
DSH_WECHAT_DESKTOP_GRACE_MS=5000
```

每次判断时现读，改完下一条消息就生效。

## 还原

```bash
python scripts/install.py --rollback
```

会把 `host.js` 换回插件原版（`files/host.js.original-0.46.0`，193796 字节）。重启后回到原版行为。

## 包里有什么

| 路径 | 作用 |
| --- | --- |
| `files/host.js` | 打过补丁的插件主文件，209130 字节 |
| `files/host.js.original-0.46.0` | 0.46.0 原版，用来还原 |
| `scripts/install.py` | 安装/检查/还原，默认 dry-run |
| `SKILL.md` | 本文件 |

## 补丁到底改了什么

`host.js` 里七处标记，对应四件事：

| 标记 | 作用 |
| --- | --- |
| `wechatAndDesktop` | 绑定会话：微信和桌面同时问，谁先答用谁 |
| `desktopFirstThenWechat` | 未绑定会话：先给桌面，超时才转手机 |
| `onSessionEvent` / `bufferUnboundReply` | 未绑定会话的答案不再丢弃，攒起来等任务结束发手机 |
| `questionCalls` / `rememberQuestionCall` / `takeQuestionCall` | 把真实的调用编号交给桌面，这是「手机答完框消失」的关键 |

最后那三个是整件事的难点。原版插件转给桌面的提问请求里不带调用编号，桌面卡片就自己编了个号，等手机上答完、宿主那边结算了，两边编号对不上，卡片永远删不掉。补丁在 `session/event` 的 `tool/call` 里把真编号记下来，提问时补进请求，编号对上了，结算后卡片自动消失。

## 已知限制

- 只能同时绑一个微信对话。绑了多个时，跨会话推送会拒绝发送（无法确定发给谁）。
- 微信那边一个回复窗口最多连发 10 条，超了会被拒。等用户再发一条消息就续上。
- 补丁只对 0.46.0 有效。插件升级后需要重新打。
- 子代理（subagent）不能弹人工提问，这是 DSH 自己的限制，与本补丁无关。

## 不包含什么

- 不含任何人的微信绑定信息、账号、密钥。`state.json` 是每台机器自己的，补丁不碰它。
- 不含 DSH 安装包本身的改动。这个补丁只改插件，不动 `app.asar`，风险低。
